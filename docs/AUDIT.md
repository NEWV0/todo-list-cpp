# Аудит исходного проекта todo-list-cpp

## Исходное состояние

Исходный проект представляет собой небольшое графическое приложение на C++/Qt для управления списком задач.

В репозитории присутствуют:
- `main.cpp`;
- модель задачи `Task`;
- класс окна `ToDoListApp`;
- сохранение и загрузка задач;
- JSON-кэш;
- возможность прикрепления изображения.

При первичной сборке и запуске проекта были выявлены проблемы, перечисленные ниже.

## Журнал выявленных проблем

| № | Проблема | Критичность | Решение |
|---|---|---|---|
| 1 | В репозитории отсутствует воспроизводимая система сборки | High | Добавить `CMakeLists.txt` с поддержкой Qt 6 и C++17 |
| 2 | `QVBoxLayout` используется без явного подключения заголовка | High | Добавить `#include <QVBoxLayout>` |
| 3 | Приложение падает при запуске: `centralWidget()` используется до установки центрального виджета | High | Создать `QWidget` и установить его через `setCentralWidget()` |
| 4 | В проекте отсутствуют автоматические тесты | High | Добавить модульные тесты |
| 5 | Отсутствует CI | Medium | Добавить GitHub Actions со сборкой и запуском тестов |
| 6 | Логика работы с задачами, файлами и GUI сосредоточена в `ToDoListApp` | Medium | Не выполнять большой рефакторинг, но отделить тестируемую логику модели `Task` |
| 7 | Проверка пользовательского ввода минимальна | Medium | Добавить проверки там, где вводятся новые поля и выполняются действия над выбранной задачей |
| 8 | Имена файлов `tasks.txt` и `cached_tasks.json` жестко заданы в коде | Low | Оставить текущий формат для совместимости, зафиксировать ограничение в документации |
| 9 | Формат `tasks.txt` зависит от разделения полей символом табуляции и не имеет версии формата | Medium | Не расширять текстовый формат без необходимости; для новых данных использовать JSON-кэш |
| 10 | В исходной модели нет приоритета, дедлайна, тегов, удаления и поиска | Medium | Реализовать пять новых функций: Priority, Deadline, Tags, Delete, Search |

## План доработки

Для выполнения практической работы планируется:

1. Добавить сборку через CMake.
2. Исправить ошибки, мешающие сборке и запуску проекта.
3. Добавить пять новых функций:
   - приоритет задачи;
   - дедлайн;
   - теги;
   - удаление выбранной задачи;
   - поиск по задачам.
4. Добавить модульные тесты.
5. Интегрировать тесты с CTest.
6. Настроить GitHub Actions.
7. Организовать работу через GitHub Projects.
8. Подготовить сценарий демонстрации и отчет.
